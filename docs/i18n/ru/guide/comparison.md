# Сравнение с Gotenberg и moalhaddar/docx-to-pdf

<!-- languages:end -->

Ещё два сервиса превращают офисные документы в PDF по HTTP с помощью LibreOffice. **Gotenberg** — самый
распространённый: универсальный API для документов вокруг Chromium, LibreOffice и инструментов для PDF.
**moalhaddar/docx-to-pdf** — сервис, интерфейс которого сохраняет этот. Эта страница рассказывает, что делает каждый,
а затем сравнивает скорость, память и то, что каждый делает с враждебным документом.

Каждая цифра на этой странице взята из сырых результатов трёх полных сравнительных прогонов `make compare` — сравнения,
которое может повторить любой ([Как это повторить](#как-это-повторить)); страница
[Benchmarks](https://oxidestack.github.io/docx-to-pdf/benchmarks/) показывает каждую цифру последнего прогона и сырые
результаты каждого. Сборка сайта записывает цифры ниже из этих файлов и падает на цифре, набранной здесь вручную.
Внутри прогона цифра — это среднее ± σ (n) по блокам прогона, где σ — выборочное стандартное отклонение, и две цифры
различаются, когда разрыв между ними больше 2σ = 2·√(σ₁²/n₁ + σ₂²/n₂); диапазон берётся по прогонам, и цифра каждого
прогона — один из его концов или лежит между ними; где цифра получена в одном прогоне, страница так и говорит.

## Что выбрать

- **Gotenberg** — когда задача шире, чем документы Word в PDF: HTML, URL или Markdown через Chromium, электронные
  таблицы и презентации, слияние и разделение PDF, PDF/A или PDF/UA, вебхуки или параметры в запросе (диапазоны
  страниц, водяной знак, пароль). Он делает всё это, и за ним годы работы в продакшене.
- **oxidestack/docx-to-pdf** — когда задача — документы Word в PDF за один вызов HTTP, в больших объёмах, из
  документов, которые вы не контролируете. На измеренной нагрузке в каждом из трёх чередующихся прогонов он потратил
  меньше CPU и меньше памяти, чем Gotenberg, и конвертировал больше документов в секунду
  ([соотношения](#скорость-и-память)), а враждебный документ останавливается на ограничении, а не продолжает работать
  ([случаи](#враждебные-документы)).
- **moalhaddar/docx-to-pdf** — только чтобы сохранить ровно то, что он делает сегодня, включая вёрстку LibreOffice
  7.3. Чтобы уйти с него, [руководство по переходу](migration.md) перечисляет, что меняют клиент и развёртывание.

## Что делает каждый

Столбец Gotenberg сверен с его документацией и исходным кодом той версии, которая измерялась; её называет раздел
[Скорость и память](#скорость-и-память).

| | Gotenberg | moalhaddar/docx-to-pdf | oxidestack/docx-to-pdf |
| --- | --- | --- | --- |
| Что конвертирует | любой формат, который открывает LibreOffice (текстовые документы, электронные таблицы, презентации, рисунки), а также HTML, URL и Markdown через Chromium | документы Word (DOCX, DOC, ODT, RTF и их варианты); всё остальное передаётся LibreOffice без проверки | только документы Word: DOCX, DOCM, DOTX, DOC, ODT, OTT, плоский ODT, RTF ([принимаемые форматы](api.md#принимаемые-форматы)) |
| Маршруты конвертации | `/forms/libreoffice/convert`, `/forms/chromium/convert/url`, `/forms/chromium/convert/html`, `/forms/chromium/convert/markdown` и снимки экрана для каждого входа Chromium | `POST /pdf`, `POST /docx-to-pdf` | `POST /pdf`, `POST /docx-to-pdf` |
| Как определяется формат | по расширению имени файла | не проверяется | по байтам документа; всё остальное — `415` до того, как его увидит LibreOffice |
| Параметры запроса | много на маршруте LibreOffice: диапазоны страниц, альбомная ориентация, пароль, PDF/A и PDF/UA, слияние нескольких файлов в один, водяной знак, тегированный PDF | нет | нет |
| Инструменты для PDF | слияние, разделение, PDF/A и PDF/UA, метаданные, закладки, вложения, Factur-X, сведение, оптимизация, водяной знак, штамп, поворот, шифрование (`/forms/pdfengines/…`) | нет | нет |
| Асинхронная работа | вебхуки; входной файл, загружаемый по URL (`downloadFrom`) | нет | нет |
| Аутентификация, TLS | базовая аутентификация или OIDC; TLS | не документированы | нет: поставьте его за свой ingress |
| Конвертация, которая идёт слишком долго | API отвечает `503` по своему тайм-ауту (`API_TIMEOUT`, по умолчанию `30s`); LibreOffice продолжает работать с документом | тайм-аута нет | убивается по `DOCX_TO_PDF_CONVERSION_TIMEOUT` (по умолчанию `180s`) с ответом `504`; экземпляр заменяется |
| Документ, которому нужно слишком много памяти | собственного ограничения нет | собственного ограничения нет | экземпляр убивается при превышении `DOCX_TO_PDF_INSTANCE_HARD_MEMORY` (по умолчанию `2GiB`), а запрос получает ответ `413`; ZIP, который распаковывается больше `DOCX_TO_PDF_MAX_INFLATED_SIZE` (`256MiB`), получает `413` до конвертации |
| Изображение, слишком большое для LibreOffice | отбрасывается, ответ `200` | отбрасывается, ответ `200` | уменьшается, и об этом сообщает заголовок `Docx-To-Pdf-Pictures` |
| Связанное изображение в документе | не загружается | загружается, с публичных и частных адресов | не загружается |
| LibreOffice | 26.8.1, перезапускается после `LIBREOFFICE_RESTART_AFTER` конвертаций (по умолчанию `10`) | 7.3 | 26.8, экземпляр заменяется после `DOCX_TO_PDF_INSTANCE_MAX_CONVERSIONS` конвертаций (по умолчанию `200`) или при превышении потолка памяти |
| Телеметрия | трассы, метрики и логи OpenTelemetry; Prometheus | нет | трассы, метрики и логи OpenTelemetry; Prometheus `GET /metrics` |
| Образы | amd64, arm64 и ещё три архитектуры | только amd64 | amd64 и arm64 |

Ограничения в столбце oxidestack/docx-to-pdf — его значения по умолчанию; каждое из них — настройка
([Конфигурация](configuration.md)). Строка о связанных изображениях и строки об ограничениях измерены в тесте на
враждебных документах ниже; у Gotenberg и moalhaddar/docx-to-pdf — так, как каждый поставляется.

## Чего не скажут цифры

- **Один vCPU, один LibreOffice, одна смесь документов.** Gotenberg запускает один LibreOffice на контейнер, поэтому
  именно эта ячейка сравнивается напрямую; больший пул против нескольких контейнеров Gotenberg не измерялся.
- **Один вид хоста.** Абсолютное время или цифра CPU меняется между виртуальными машинами одной конфигурации, а
  соотношение, измеренное внутри одного чередующегося прогона, меняется меньше, но всё же больше собственной
  стандартной ошибки: отсюда диапазон по прогонам. Все прогоны были на amd64: у moalhaddar/docx-to-pdf нет образа для
  arm64, и прогона на arm64 в результатах нет.
- **Один образ на прогон.** Последний прогон измерял тот единственный образ oxidestack/docx-to-pdf, который назван в
  разделе выше, более ранние прогоны — код до него; более поздний релиз измеряется более поздним прогоном.
- **Один прогон на сторону для каждого враждебного документа.** Ответы повторяются, потому что их задают ограничения;
  время или пик — одно измерение.
- **Память за тысячи конвертаций.** Длительные прогоны на
  [Benchmarks](https://oxidestack.github.io/docx-to-pdf/benchmarks/#soaks) — по одному на сторону, и этого
  недостаточно, чтобы решить, растёт ли память сервиса: эта страница называет уровень, который измерил длительный
  прогон oxidestack/docx-to-pdf, и ничего не утверждает о росте.

Где Gotenberg справляется с враждебным документом так же или лучше: он тоже не открывает сетевых соединений, он
конвертирует `tdf38575` и раньше сдаётся на застрявшей загрузке. Где он отличается: его ответ по тайм-ауту не
останавливает LibreOffice, который продолжает работать с документом, пока запросы за ним отклоняются.

## Рендеринг

Рендеринг Gotenberg никогда не измерялся: ни один PDF из Gotenberg не сравнивался с PDF oxidestack/docx-to-pdf, поэтому
эта страница ничего о нём не утверждает. Оба работают на LibreOffice 26.8, так что разница ожидалась бы в шрифтах и
параметрах экспорта, а не в вёрстке, и это ожидание не измерено. По сравнению с moalhaddar/docx-to-pdf документы,
которые различаются, различаются там, где LibreOffice 7.3 и 26.8 по-разному верстают страницу;
[руководство по переходу](migration.md) говорит, что следует проверить развёртыванию, которое переходит.

## Как это повторить

`make compare` запускает каждый сервис с нуля, прогоняет ячейки скорости блоками (каждый блок запускает каждый сервис
по одному разу в перемешанном порядке, так что дрейф хоста сдвигает все сервисы одинаково), затем враждебные
документы и длительные прогоны и печатает обе таблицы. Нужен только Docker.

```sh
make compare QUICK=1   # minutes on a laptop: one short block and four hostile documents
make compare           # the full run, for a quiet VM: hours
```

Быстрый режим показывает, что команда работает; его числа несравнимы с приведёнными выше. Полный режим записывает
`results.json`, подобный тому, из которого читается эта страница, сравнимый на хосте того же вида, а
moalhaddar/docx-to-pdf работает только на amd64. Что он запускает и чего не показывает, описано в
[examples/compare](../../../../examples/compare/README.md).
