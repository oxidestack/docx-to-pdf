Для тех, кто запускает `moalhaddar/docx-to-pdf` (2.1.0-x) или вызывает его и хочет перейти на этот сервис. Он
конвертирует те же документы через тот же интерфейс, с актуальным LibreOffice, без сбоев оригинала и со встроенным
OpenTelemetry. Эта страница говорит, что остаётся прежним, что меняет клиент, что меняет развёртывание, и в конце —
каждое намеренное отличие с его причиной. Тест сверяет страницу со списком отличий и с другими страницами
руководства, поэтому отличие не может существовать без строки здесь.

## Что остаётся прежним

- Порт **8080**.
- `POST /pdf` и `POST /docx-to-pdf`, тело `multipart/form-data` с документом в файловой части с именем
  **`document`**. Имя файла части и её `Content-Type` не играют роли.
- Успех — **`200`**, `Content-Type: application/pdf`, PDF в теле.
- Кросс-доменные запросы к этим двум путям: `Access-Control-Allow-Origin: *` и ответ на предварительный запрос с
  `Access-Control-Allow-Methods: POST`, разрешёнными запрошенными заголовками и `Access-Control-Max-Age: 1800`.
- Документы, которые конвертируются: DOCX, DOC, ODT и RTF, а также варианты семейства Word, которые оригинал
  действительно конвертирует: DOCM, DOTX, OTT и плоский ODT ([принимаемые форматы](api.md#принимаемые-форматы)).
- Вид PDF: те же страницы, размеры страниц и слова. PDF не совпадает байт в байт, потому что LibreOffice новее.
- Свободные шрифты, которые поставлял оригинал, и те же замены для распространённых шрифтов Word, таких как Calibri,
  Arial и Times New Roman ([Шрифты](operations.md#шрифты)).

Клиенту, который отправляет документ, читает PDF в ответ и считает любой другой ответ неудачей, ничего менять не
нужно.

## Что меняет клиент

### Статусы

Оригинал отвечал на большинство ошибок `500`, а на некоторые входные данные, которые не являются документами, — PDF.
Этот сервис отвечает на каждую ситуацию своим статусом, и тело каждой ошибки — документ problem
([Ошибки](api.md#ошибки)).

| Ситуация | moalhaddar/docx-to-pdf | Этот сервис | Повторять? |
| --- | --- | --- | --- |
| Тело не multipart, повреждено или не содержит файловой части с именем `document` | 500 или 400 | 400 | нет |
| Неизвестный путь, включая каждый путь `/actuator` | 404 | 404 | нет |
| Известный путь с другим методом (`GET /pdf`) | 405 | 405 | нет |
| Ни один байт запроса не приходит две минуты | 500 | 408 | нет |
| Документ больше ограничения размера (по умолчанию 10 MiB) | 500, после загрузки | 413, до загрузки остального | нет |
| Zip-бомба или документ, которому нужно больше памяти, чем может занять экземпляр | ограничения нет: у контейнера раньше кончается память или диск | 413 | нет |
| Текст, пустой файл, электронная таблица, изображение, случайные байты | 200, PDF из того, что LibreOffice из этого сделал | 415 | нет |
| Документ, который LibreOffice не может открыть | 500 | 422 | нет |
| Все экземпляры заняты дольше ограничения ожидания, очередь полна, сервис запускается или останавливается | ожидание без ограничения | 503 с `Retry-After` | да, после `Retry-After` |
| Конвертация, которая идёт дольше тайм-аута конвертации (по умолчанию 3 минуты) | ожидание без ограничения | 504 | не больше одного раза |
| Всё остальное | 500 | 500 | нет |

Что изменить:

- **Тела ошибок.** Документа Spring `{"timestamp","status","error","path"}` и HTML-страницы «Whitelabel Error Page»
  больше нет. Клиент, который их читает, читает `status` или только HTTP-статус. Не сопоставляйте по `detail`: это
  неизменная фраза для каждой ситуации, предназначенная человеку ([все ошибки](api.md#все-ошибки-сервиса)).
- **Повторы.** Оригинал никогда не отказывал в работе, поэтому единственным сбоем клиента был его собственный
  тайм-аут чтения. Этот сервис отвечает `503`, когда перегружен. Клиенту, который повторяет только ошибки соединения,
  следует повторять и `503` после `Retry-After`, который тот несёт; повторить `504` один раз разумно; `4xx` при
  повторе не изменится.
- **Тайм-аут чтения.** Задайте его больше ограничения ожидания плюс тайм-аут конвертации, по умолчанию 60 + 180
  секунд, с запасом, чтобы клиент получил `503` или `504` сервиса, а не обрывал соединение сам.
- **Входные данные, которые не являются документами.** Простой текст, пустые файлы и другие форматы теперь получают
  `415`. Сначала конвертируйте их в DOCX.
- **Изменённые изображения.** `200` может нести `Docx-To-Pdf-Pictures: downscaled=<n>, replaced=<n>`, когда
  изображение, слишком большое для безопасной конвертации, было уменьшено или заменено ([Изображения, изменённые
  перед конвертацией](api.md#изображения-изменённые-перед-конвертацией)). Клиент, который хочет сообщить об этом
  своему пользователю, читает этот заголовок; любой другой может его игнорировать.

## Что меняет развёртывание

### Проверки здоровья и метрики

| Назначение | moalhaddar/docx-to-pdf | Этот сервис |
| --- | --- | --- |
| Живость | `GET /actuator/health/liveness` | `GET /livez` |
| Готовность и ожидание запуска | `GET /actuator/health/readiness`, `GET /actuator/health` | `GET /readyz` |
| Метрики Prometheus | — | `GET /metrics` |
| Трассы, логи и метрики по OTLP | — | задайте `OTEL_EXPORTER_OTLP_ENDPOINT` |

Каждый путь `/actuator` отвечает `404`, поэтому замените каждую ссылку на него: пробы Kubernetes, стратегии ожидания
Testcontainers (`.forPath("/actuator/health")` превращается в `.forPath("/readyz")`), проверки мониторинга, скрипты.
[Проверки здоровья](operations.md#проверки-здоровья) говорят, что отвечает каждый путь и сколько должна ждать проверка
запуска; [Метрики](operations.md#метрики) перечисляют каждую метрику, а [Телеметрия](configuration.md#логи-и-телеметрия)
— настройки OpenTelemetry.

### Настройки

Каждая настройка — переменная окружения; [Конфигурация](configuration.md) перечисляет их все со значениями по
умолчанию. Для развёртывания moalhaddar/docx-to-pdf меняется только то, что оно раньше задавало:

| Настройка moalhaddar/docx-to-pdf | В этом сервисе |
| --- | --- |
| `SERVER_PORT` | По-прежнему читается. Когда заданы обе, побеждает `DOCX_TO_PDF_PORT`. |
| `POOL_SIZE`, `pool.size` | По-прежнему читаются, в этом порядке. `DOCX_TO_PDF_POOL_SIZE` побеждает обе. |
| `SPRING_SERVLET_MULTIPART_MAX_FILE_SIZE`, `SPRING_SERVLET_MULTIPART_MAX_REQUEST_SIZE` | Не читаются: задайте `DOCX_TO_PDF_MAX_DOCUMENT_SIZE`. Значение вроде `1000MB` сохраняет свой смысл. Если ничего не менять, ограничение — 10 MiB, и документ больше получает `413`. |
| `SERVER_TOMCAT_CONNECTION_TIMEOUT` | Не читается: ближайшая настройка — `DOCX_TO_PDF_IDLE_TIMEOUT`, длительность, а не миллисекунды; `120000` — её значение по умолчанию, `120s`. |
| `SERVER_TOMCAT_MAX_HTTP_FORM_POST_SIZE` | Не читается, и ничто её не заменяет: ни один путь не принимает форму в кодировке URL. |
| `JAVA_TOOL_OPTIONS` | Не читается: JVM нет. `-Dpool.size` в ней тоже не читается. Память рассчитывается от `DOCX_TO_PDF_INSTANCE_HARD_MEMORY` ([Расчёт ресурсов](operations.md#расчёт-ресурсов)). |
| `LOGGING_LEVEL_*` | Не читается: `RUST_LOG`. |
| остальные `SPRING_*`, `SERVER_TOMCAT_*`, `MANAGEMENT_*` | Не читаются. Удалите их. |

Две новые настройки стоит посмотреть в любом развёртывании: `DOCX_TO_PDF_CONVERSION_TIMEOUT` и
`DOCX_TO_PDF_POOL_WAIT_TIMEOUT`, которые ограничивают то, чего оригинал ждал без ограничения.

### Память, диск и CPU

Без JVM память контейнера определяют экземпляры LibreOffice. Каждый убивается и заменяется, а его запрос получает
`413`, если превышает `DOCX_TO_PDF_INSTANCE_HARD_MEMORY` (по умолчанию 2 GiB), поэтому ограничение памяти в
256 MiB + размер пула × (это ограничение + 256 MiB) не может быть превышено, какими бы ни были документы.
Развёртывание, которое подняло ограничение документа для больших документов с изображениями, поднимает вместе с ним и
жёсткое ограничение памяти. `/tmp` должен быть доступен для записи, по умолчанию на диске.
[Расчёт ресурсов](operations.md#расчёт-ресурсов) даёт формулы и пробу, которая измеряет вашу собственную машину.

### Образ

- Собран для `linux/amd64` и `linux/arm64`: на машине Arm, включая Apple Silicon, он работает нативно, а не под
  эмуляцией.
- Он работает от пользователя `10001` без записи в passwd, подходит и любой другой пользователь не root, корневая
  файловая система может быть только для чтения, а `/tmp` — единственный каталог, в который он пишет
  ([Контейнер](operations.md#контейнер)).
- PID 1 — `tini`; `SIGTERM` запускает плавную остановку. Дайте среде выполнения время на остановку плюс около 40
  секунд, прежде чем она убьёт процесс ([Остановка](operations.md#остановка)).
- В нём нет HTTP-клиента, поэтому нет и Docker `HEALTHCHECK`: используйте HTTP-проверки оркестратора.
- Два шрифта, которые нёс оригинальный образ, Brown Std и GE Dinar Two, распространяются по коммерческим лицензиям и
  в этот образ не входят: документы, набранные ими, получают замену. Подключите файлы шрифтов, на которые у вас есть
  лицензия ([Подключение своих шрифтов](operations.md#подключение-своих-шрифтов)).

### Сеть

Сервис не открывает собственных соединений, кроме как к коллектору OpenTelemetry, если он задан. NetworkPolicy
чарта Helm включена по умолчанию и ограничивает под этим: входящий трафик только на порт 8080, исходящий — к DNS (UDP
и TCP 53, к подам `kube-dns` кластера) и только к порту `otel.endpoint`. Кластер с локальным для узла кешем DNS
задаёт его адрес в `networkPolicy.dnsTo`, коллектор, доступный только по заданным адресам, задаётся в
`networkPolicy.otlpTo`, а `networkPolicy.enabled: false` оставляет сеть пода вашей собственной политике
([Сеть](installation.md#сеть-сервис-ничего-не-загружает)).

### Чек-лист

1. Замените ссылку на образ образом этого сервиса.
2. Замените каждый `/actuator/health*` на `/livez` для живости и на `/readyz` для готовности и ожидания запуска.
3. Переведите настройки по таблице выше и удалите те, что не читаются.
4. Поднимите тайм-аут чтения клиента выше ограничения ожидания плюс тайм-аут конвертации и повторяйте `503` после
   `Retry-After`.
5. Найдите код, который разбирает тело ошибки оригинала, полагается на `500` или отправляет что-то, кроме
   текстового документа.
6. Направьте `OTEL_EXPORTER_OTLP_ENDPOINT` на коллектор или собирайте `/metrics`.
7. Запустите тесты клиента против нового образа.

## Все намеренные отличия

Каждое отличие ниже сделано намеренно: ошибка оригинала, которая не перенесена, ограничение, которого у него не
было, или деталь Spring, которая не входит в интерфейс. Сам PDF отличается только тем, как его верстает более новый
LibreOffice.

| Отличие | moalhaddar/docx-to-pdf | Этот сервис | Почему |
| --- | --- | --- | --- |
| Более новый LibreOffice | LibreOffice 7.3: номера страниц и номера списков в некоторых полях остаются пустыми, длинная плавающая таблица подвешивает конвертацию, на странице на одну строку меньше при междустрочном интервале Word 1.15 | Актуальный LibreOffice: эти поля заполнены, эта таблица конвертируется меньше чем за секунду, на странице на одну строку больше; слова те же | LibreOffice 7.3 больше не поддерживается, а более новый лучше отрисовывает эти документы. |
| Изображения в PDF | каждое изображение декодируется и уменьшается не более чем до 300 DPI | встраиваются как есть, JPEG байт в байт; `DOCX_TO_PDF_PDF_MAX_IMAGE_DPI=300` уменьшает их, как оригинал | Типичный отчёт конвертируется с третью CPU, и изображения ничего не теряют; изображение, размещённое с разрешением выше 300 DPI, даёт PDF больше. |
| Содержимое вне документа | изображение, связанное с URL или файлом, удалённый шаблон или связь OLE могут загружаться | никогда не загружается и не читается: связанное изображение конвертируется во встроенную копию или ни во что | Документ не должен заставлять сервис обращаться к другим хостам его сети или ждать хост, который никогда не ответит. |
| Китайский, японский и корейский текст | шрифта для него нет: пустые прямоугольники или неверная замена | отрисовывается шрифтами Noto CJK | Текст на этих письменностях должен читаться в PDF. |
| Запрос, который не является загрузкой формы | 500 или 400 с ошибкой Spring | 400 | Запрос — ошибка клиента, а это и говорит 4xx. |
| Документ больше ограничения размера | 500 после всей загрузки | 413, до того как прочитан остаток тела | Слишком большая загрузка — ошибка клиента, а дочитывать её до конца сервису обходится впустую. |
| Файл, который не является текстовым документом | 200, PDF из того, что LibreOffice из него сделал, RTF за меткой порядка байтов набран как собственная разметка | 415 | PDF из мусора выглядит как успех; принимаются только форматы, которые оригинал действительно конвертирует. |
| Повреждённый документ | 500 | 422 | Виноват документ, а не сервис. |
| Документ, которому нужно слишком много памяти | ограничения нет: у контейнера кончается память, и все конвертации в нём теряются | сразу 413; экземпляр заменяется, другие конвертации продолжаются | Один документ не должен ронять весь сервис. |
| Zip-бомба | проверки нет: LibreOffice распаковывает её на диск при загрузке | 413 до любой конвертации | Несколько мегабайт не должны заполнять гигабайты диска и памяти. |
| Изображение, слишком большое для декодирования | 200; больше примерно 1 GiB в декодированном виде изображение молча пропадает | 200 с уменьшенным изображением или заглушкой вместо него и заголовком `Docx-To-Pdf-Pictures`, который об этом говорит | Молча терять содержимое — ошибка, а отказ в документе оставил бы клиента ни с чем. |
| Конвертация, которая не заканчивается | ответа нет, экземпляр занят, пока она идёт | 504 после тайм-аута конвертации, экземпляр заменяется | Зависший документ не должен вечно занимать экземпляр и клиента. |
| Запросов больше, чем экземпляров | они ждут без ограничения | ограниченная очередь; сверх неё или после ограничения ожидания — 503 с `Retry-After` | Клиенту следует узнать, что сервис перегружен, а запрос может принять другая реплика. |
| Медленная загрузка | 500, когда загрузка замирает на несколько миллисекунд, как бывает в реальных сетях | ожидается, сколько бы ни длилась вся загрузка | Пауза в сети — не ошибка клиента. |
| Клиент, который перестал отправлять | 500 после тайм-аута соединения | 408 после двух минут без единого байта, соединение закрывается | Клиент остановился, а это и говорит 408. |
| Клиент, который отключается во время конвертации | конвертация продолжается и занимает экземпляр | конвертация останавливается, а экземпляр сразу освобождается | Этот PDF никто не ждёт. |
| Тела ошибок | документ JSON Spring или HTML-страница для браузера | `application/problem+json`, чей `detail` никогда не называет конвертер | Стандартный формат для ошибок HTTP, без внутренностей фреймворка. |
| Проверки здоровья и метрики | Spring Actuator под `/actuator`; проверка здоровья отвечает `UP`, пока единственный экземпляр завис в конвертации | `/livez`, `/readyz` и `/metrics`; `/readyz` отвечает `503`, пока ни один экземпляр не может принять конвертацию | Готовность должна говорить, можно ли обслужить запрос сейчас, чтобы трафик шёл реплике, которая может. |
| Проба платформы | нет | `POST /probe` на собственном порту, выключенная по умолчанию, измеряет машину для расчёта ресурсов | Расчёту ресурсов развёртывания нужны цифры с той машины, на которой оно работает. |
| Кросс-доменные запросы вне конвертации | 403 `Invalid CORS request` на предварительный запрос к другому пути или для другого метода и заголовки `Allow` Spring | кросс-доменной обработки вне двух путей конвертации нет; ответ на предварительный запрос называет только `POST` | Браузер сам применяет кросс-доменные правила; 403 и эти заголовки были от Spring. |
| Экземпляр, который не запускается | сервис не запускается | запуск повторяется, до трёх раз, а `/readyz` тем временем отвечает `503` | Временный сбой не должен загонять сервис в цикл перезапусков. |
| Пул больше числа CPU | запуск может зависнуть навсегда, когда пул больше числа CPU, которые видит JVM | каждый экземпляр запускается при любом размере пула | Запуск, который никогда не заканчивается, — ошибка. |
| Настройки Spring, Tomcat и JVM | читаются | не читаются; их замены — в разделе [Настройки](#настройки) | В этом сервисе нет ни Spring, ни Tomcat, ни JVM. |
